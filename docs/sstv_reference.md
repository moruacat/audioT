# SSTV 技术参考（Martin M1 / Robot 36）

本文记录 AudioT 内置 SSTV 实现所依据的时序规范、实现取舍，以及**已经验证/尚未验证**的部分。

> 合规提醒：本功能仅限个人学习与实验，未取得业余无线电执照不得用于空口发射。
> 详见 [SSTV_免责声明.md](SSTV_免责声明.md)。

## 1. 为什么重写（历史教训）

AudioT 在 1.4.x 曾实现过 9 种 SSTV 模式（约 1978 行），随后在提交 `a93fb53` 被整体删除，
理由是"修复历史彩色与栅格化缺陷反复"。

对旧代码考古后定位到四个根因：

1. **模式表的 `lineTimeMs` 语义填错**：Martin M1 填了 146.432（那是**一个色彩段的扫描时长**），
   真实整行是 446.446 ms；Robot 36 填了 88.0，真实整行是 150 ms。行速整体快约 3 倍。
   旧文档里"Martin M1 ≈38.2 s / Robot 36 ≈21.8 s"正是从这个错表推出来的，
   **正确值是 ≈114.3 s 与 36.0 s**（Robot 36 的模式名就是它的帧长）。
2. **用"同步 + 剩余时间三等分"套所有模式**：漏掉 Martin M1 的 porch（同步后 0.572 ms 的
   1500 Hz），色彩顺序被一刀切成 R-Y/B-Y/Y（实际是 G-B-R）。
3. **Robot 36 结构上就不是三等分**：4:2:0 交织——每行发全分辨率 Y（88 ms），
   再发一个色差分量（44 ms / 160 采样），偶行 Cr、奇行 Cb。
4. **最致命**：编码器与解码器共用同一张错表，往返自测永远通过，缺陷从不暴露。

因此本次改为**显式逐段时序表 + 行型序列**（`src/core/sstv/sstv_protocol.*`），
并配套三层测试（见第 5 节）。

## 2. 通用头部（880 ms）

| 段 | 时长 | 频率 |
|---|---|---|
| leader | 300 ms | 1900 Hz |
| break | 10 ms | 1200 Hz |
| VIS 起始位 | 300 ms | 1200 Hz |
| VIS 数据位 ×7（LSB first） | 30 ms ×7 | 1100 Hz = 1，1300 Hz = 0 |
| 偶校验位 | 30 ms | 同上 |
| 停止位 | 30 ms | 1200 Hz |

VIS 码：Martin M1 = **44**，Robot 36 = **8**。

## 3. Martin M1（320×256，整行 446.446 ms）

| # | 段 | 时长 ms | 频率 |
|---|---|---|---|
| 1 | Sync | 4.862 | 1200 |
| 2 | Porch | 0.572 | 1500 |
| 3 | G 扫描 | 146.432 | 1500–2300（320 px，0.4576 ms/px）|
| 4 | Separator | 0.572 | 1500 |
| 5 | B 扫描 | 146.432 | 同上 |
| 6 | Separator | 0.572 | 1500 |
| 7 | R 扫描 | 146.432 | 同上 |
| 8 | Separator | 0.572 | 1500 |

- 图像部分 256 × 446.446 ms = **114.29 s**；含头部 **115.17 s**。
- 像素映射：`f = 1500 + 800 × v/255`。

## 4. Robot 36（320×240，整行 150 ms）

| 行型 | 段序列 |
|---|---|
| 偶行（Cr） | Sync 9.0/1200 → Porch 3.0/1500 → **Y 88.0**（320 px）→ Sep 4.5/1500 → Porch 1.5/1900 → **Cr 44.0**（160 采样）|
| 奇行（Cb） | 同上，Sep 4.5/**2300**，末段为 **Cb 44.0** |

- 自洽校验：Y 88/320 = 0.275 ms/px，色度 44/160 = 0.275 ms/采样（同一像素时钟）。
- 240 × 150 ms = **36.00 s**；含头部 **36.88 s**。
- 色差编码（BT.601）：`Y = 0.299R + 0.587G + 0.114B`，
  `Cr = (R−Y)×0.713 + 128`，`Cb = (B−Y)×0.564 + 128`，中性 1900 Hz。
- 编码端色度水平做 2:1 盒滤波（两像素平均）；解码端水平 160→320 线性插值、
  垂直方向对缺失分量用上下最近的同类行插值。

## 5. 实现要点（都是踩过的坑）

### 编码（`sstv_encoder.cpp`）

- **段/像素边界一律用"从帧首起的绝对毫秒"换算样本**：
  `sample = llround(ms × sr / 1000)`。
  Martin M1 一行是 446.446 ms × 44.1 = **19688.27 个样本**（非整数）；
  若改成"按行内比例缩放以强制行长为整数"，行内每个边界都会挪动最多 0.27 个样本，
  实测波形与标准参考的失配率高达 **81%**（边界差 1 个样本会让其后相位整体跳变）。
- **时序表用 `double` 而不是 `float`**：`146.432f` 实际是 146.4320068359375，
  乘以采样率后个别边界差 1 个样本，后果同上。
- 全帧相位连续；容量一次性 `reserve`（旧代码"每段 reserve(size+n)"是 O(n²) 拷贝）。

### 解码（`sstv_decoder.cpp`）

- **长音用 Goertzel**（leader / VIS 位 / sync，窗口 3~30 ms）；
  **像素用相位差分鉴频**：M1 每像素仅约 20 个样本，Goertzel 的频率分辨力
  `fs/N ≈ 2.2 kHz` 远大于 800 Hz 的信号带宽，完全不可用。
- **低通级数决定图像噪声**：混频后残留的 −2f0 镜像（约 3800 Hz）会造成相位摆动，
  而相位差分是逐样本求差，摆动被放大成 `δφ × f_img` 的频率误差。
  两级一阶（截止 600 Hz）只有 −32 dB，实测灰图出现 **±19 个灰阶的周期性条纹**；
  改为**四级一阶、截止 700 Hz**（约 −60 dB）后，灰图误差降到 **±1 个灰阶**。
- 每个像素不做 `atan2`：把窗口内所有 `z[n]·conj(z[n−1])` 复数累加后只算一次，
  这在数学上等于窗口内相位增量的平均（即平均频率），噪声被平均掉。
- **行同步必须"跟踪 + 最小二乘拟合"**：M1 一行 446 ms，0.1% 时钟偏差在 239 行后
  累积 35 ms。先用 Goertzel 做很轻的 sync 预扫描（按实测行距做 EMA 跟踪），
  再拟合 `n = a + b·line`。
  - 搜索半宽必须能**完整覆盖一个 sync 段**（`3 ms + syncSamples/2 + 1 ms`），
    否则高比值区间被边界截断、质心左移，误差逐行累积
    （Robot 36 的 sync 有 9 ms，用固定 ±3 ms 时只锁到约 7 行）。
  - 取"高比值区间的质心"，而不是最左位置。
  - **第 0 行不检测**（它前面是 VIS 停止位，同为 1200 Hz，连成一片），
    且第一次搜索的中心必须是"第 1 行的名义位置"，不能用 headerEnd。
- sync 检测必须有阈值（`p1200 / p1500 ≥ 2` 且绝对功率下限），
  否则任何音频都会被判成"每行都锁到同步"，置信度假性 100%。
- 采样率低于 22050 Hz 直接拒绝：R36 每像素只剩约 6 个样本，无法可靠解调。

## 6. 验证状态

| 层 | 内容 | 状态 |
|---|---|---|
| A 表结构自检 | 段时长之和、像素数、分量覆盖、帧长对公开值、VIS 合法 | ✅ 通过 |
| B 波形核对 | 生产编码器 vs 测试内**独立按标准字面常量**合成的参考波，逐样本比对 | ✅ 通过（失配 <0.5%）|
| B 负对照 | 旧"漏 porch"模型、"色彩顺序错"模型、"三等分"模型 | ✅ 均被拒（失配 >10%）|
| C 独立生成器 → 生产解码器 | 尺寸精确、像素误差统计 | ✅ M1 与 R36 均通过（≥98% 像素在 8 灰阶内）|
| C 负例 | 静音、错 VIS（60）、采样率过低、旧"行速快 3 倍"模型 | ✅ 均被拒绝或低置信 |
| C 鲁棒性 | 10 dB AWGN、0.1% 采样时钟偏移 | ✅ 通过 |
| **D 外部预言机** | 导出的 WAV 交给 MMSSTV / QSSTV 等外部软件出图 | ⬜ **尚未做（需人工验收）** |

> D 层是唯一能最终确证"色彩顺序与色度约定"的验收手段。
> 如果外部软件解出的颜色不对，优先检查 Martin M1 的三段顺序（本实现按多数来源取 **G-B-R**）
> 与 Robot 36 的色差中性频率（本实现取 1900 Hz）。

## 7. 已知的来源冲突

1. **Martin M1 三段顺序**：有 G-B-R 与 G-R-B 两种说法，本实现取 **G-B-R**。
2. **Martin M1 顶部 16 行**：有资料称是灰阶标定条，本实现按"256 行全为图像行"处理。
3. **Robot 36 奇行 separator 频率**：有 1500 Hz 与 2300 Hz 两种说法；
   解码端以同步锁定的**行号**决定奇偶，测到的 separator 只作校验，不作判定依据。
4. **Robot 36 色度采样点数**：160（4:2:0）与 320 在物理信号上等价
   （320 时每两个采样值相同），本实现按 160 解码。
