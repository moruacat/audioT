## 1. 软件简介

AudioT 是一款**音频数据通信软件**：将**文本或文件**调制为音频信号，通过**扬声器、磁带机、电台**等音频链路传输；接收端用**麦克风采集**或 **WAV 文件解析**还原数据。

典型应用：

| 场景 | 说明 |
|---|---|
| 磁带机传输 | 数据导出为 WAV 音频，用磁带机录制并回放，另一台电脑从录音中还原 |
| 电台/近距离声波通信 | 一台电脑从扬声器发射，另一台电脑用麦克风监听解码，类似步话机 |
| 抗干扰传输 | 内置纠错编码，对麦克风电流声、环境噪声、磁带机失真有一定抵抗能力 |

## 2. 安装与卸载

### 2.1 系统要求

- **操作系统**：Windows 7 及以上（支持 32/64 位）
- **声卡**：任意支持 44.1 kHz 采样的输入/输出设备（板载声卡即可）

### 2.2 安装

运行 `AudioT-Setup.exe`，按向导操作：

1. **组件选择页**：
   - **AudioT 主程序**（必需，不可取消）
   - **Audacity 64 位 / 32 位**（可选，二选一）：配套音频编辑软件，用于录音、查看波形、裁剪噪声。勾选其一自动取消另一个
2. **安装目录**：默认安装到当前用户的 `%LOCALAPPDATA%\Programs\AudioT`（无需管理员权限），可点击"浏览"修改
3. 安装完成后自动运行 AudioT

安装完成后，桌面和开始菜单会生成 **AudioT** 快捷方式；若安装了 Audacity，也会生成对应快捷方式。

> **提示**：Audacity 组件安装时会自动解压并配置，可能需要十几秒，请勿中断。

### 2.3 卸载

两种方式任选：

- 开始菜单 → **AudioT 卸载**（Uninstall）
- 控制面板 → 程序和功能 → 找到 "AudioT - 音频数据通信" → 卸载

## 4. 发射面板（发送数据）

发射面板用于**生成并播放**携带文本/文件数据的音频信号，或将信号**导出为 WAV 文件**。

### 4.1 操作步骤（文本发送）

1. 选择输入模式 **文本**
2. 在文本框中输入要发送的内容（如 `Hello world`）
3. 按需选择调制配置（见 4.3）
4. 点击 **开始发送**
5. 听到约 1 秒的 **1200 Hz 连续蜂鸣（准备音）** 后，数据开始发射；进度条显示发射进度
6. 发射完成后面板显示"发射完成"

### 4.2 文件发送

1. 选择输入模式 **文件**
2. 点击 **浏览...** 选择要发送的文件（任意类型，推荐小于 100 KB）
3. 点击 **开始发送**

接收端解出文件后会自动保存（见第 5、6 节）。

### 4.3 调制配置（发送前设置）

| 选项 | 可选值 | 说明 |
|---|---|---|
| 调制方式 | AFSK（默认） | 频移键控，抗干扰强，当前唯一实际生效的调制方式 |
| 纠错编码 | None / **Hamming（默认）** / Reed-Solomon | 见第 8 节 |
| 采样率 | 22050 / **44100（默认）** / 48000 | 采样率越高音质越好、抗噪越强，文件越大 |

> 收发双方应使用**相同的采样率、调制方式、纠错编码**，否则无法解码。

### 4.4 导出 WAV

- 点击 **导出 WAV...**，选择保存路径，即可将信号导出为 WAV 文件（不含发射环节）
- 导出的 WAV 与实时发射**结构完全相同**（准备音 → 数据 → 帧尾静音），可直接用磁带机录制，或用接收面板解析
- 用于磁带机场景：导出 → 用磁带机播放录音 → 另一台电脑播放磁带录音并录制为 WAV → 接收面板解析

### 4.5 注意事项

- **红色警告**：发射时扬声器会发出刺耳的调制噪音，**请勿长时间佩戴耳机近距离收听**
- 发射期间可随时点击 **停止** 中止
- 实时发射时请确保**输出设备**（扬声器）音量足够且未被静音

## 5. 接收面板（解析 WAV 文件 / 麦克风实时接收）

接收面板支持**两种输入模式**：解析已录制好的 WAV 文件（离线解码），或直接用麦克风实时接收。

### 5.1 输入模式选择

- **WAV 文件**：解析已录制的录音文件（如磁带机回放的录音）
- **麦克风（实时）**：实时监听麦克风，检测到信号自动切段解码；**解出完整数据后自动停止监听**

> 麦克风实时模式与电台模式监听互斥（共享同一输入设备）：在接收面板开始监听会自动停止电台监听，反之亦然。

### 5.2 WAV 文件解析

1. 选择输入模式 **WAV 文件**
2. 在"WAV 文件"栏点击 **浏览...** 选择录音文件
3. 点击 **开始解析**
4. 解析成功后：
   - **文本消息**：显示在"接收内容"区域
   - **文件消息**：自动弹出保存对话框，默认文件名与发送端一致
5. 解析失败时状态栏显示失败原因（如"未找到信号"、"CRC 校验失败"）

### 5.3 麦克风实时接收

1. 选择输入模式 **麦克风（实时）**，按钮变为"开始监听"
2. 点击 **开始监听**（状态显示"监听中..."，进度条为忙碌动画）
3. 对方从扬声器发射数据 → 本机麦克风捕获 → 自动切段解码
4. 解出完整数据后**自动停止监听**，文本显示在"接收内容"区域（文件消息弹出保存对话框）
5. 若检测到信号但未解出数据，状态栏提示"检测到信号但未解出数据"，可点击 **停止** 手动结束监听

### 5.4 提示

- 支持的 WAV 格式：PCM 16 位，22050 / 44100 / 48000 Hz，单/双声道均可（双声道自动取左声道）
- 录音建议：录制完整信号（准备音 + 数据 + 尾部静音），不要裁剪掉准备音
- 麦克风实时接收前，请在设置中确认**输入设备**选择正确（设置 → 输入设备）
- 若"接收内容"区域是空的，点击 **清空** 可清除历史内容

## 6. 电台面板（实时双向通信）

电台面板提供**类似聊天软件的双向通信**：一台电脑即一个"电台站"，通过扬声器发射、麦克风监听，两台电脑可同时收发（收发互不影响）。

### 6.1 操作步骤（两台电脑）

1. **双方**进入"电台"标签页
2. 双方点击 **开始监听**（麦克风采集开始，状态栏显示"监听中..."）
3. 任一方在输入框输入文本，点击 **发送**：
   - 先发出 1 秒准备音蜂鸣，随后是调制数据
   - 消息以**绿色气泡（右侧）**显示在自己一侧
4. 对方监听到信号后自动切段解码，消息以**灰色气泡（左侧）**显示，并附时间戳
5. 系统信息（监听状态、发送失败、信号未解出等）以**居中灰字**显示

### 6.2 发送文件

- 点击 **文件...** 选择文件 → **发送**。接收方解出后自动保存（保存位置同接收面板的"保存路径"）
- 文件消息在聊天记录中以文件名气泡显示

### 6.3 注意事项

- **收发设备分离**：发送走输出设备（扬声器），接收走输入设备（麦克风），因此发射期间监听照常进行
- **距离与音量**：两台电脑的扬声器与麦克风距离越近、音量越大，成功率越高；建议 1~3 米内
- 同一台电脑上可开启"监听"后自收自发（回环测试），用于验证链路是否正常
- 电台模式使用麦克风实时监听，请先在设置中确认输入设备正确

## 7. 设置对话框（设备与参数）

点击主窗口工具栏的 **设置** 按钮打开。修改后点击 **确定** 生效（发射/监听进行中不可修改）。

### 7.1 音频设备

| 选项 | 说明 |
|---|---|
| 输入设备 | 麦克风/录音设备（电台监听、实时接收用） |
| 输出设备 | 扬声器/耳机（发射用） |
| 刷新设备 | 重新枚举系统音频设备（插拔声卡后点击） |

> 首次打开设置时自动枚举设备，可能耗时 1~2 秒。虚拟声卡（如 VB-CABLE）也会出现在列表中。

### 7.2 音频参数

| 选项 | 可选值 | 说明 |
|---|---|---|
| 采样率 | 22050 / **44100（默认）** / 48000 | 需与发射端一致 |
| 缓冲区大小 | 256 / 512 / **1024（默认）** / 2048 / 4096 | 越小延迟越低；出现爆音/卡顿时可调大 |

### 7.3 调制参数

| 选项 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| 调制方式 | AFSK | AFSK | 频移键控（当前唯一） |
| Mark 频率 | 1200 Hz | 300–8000 Hz | 代表二进制 1 的载波频率 |
| Space 频率 | 2200 Hz | 300–8000 Hz | 代表二进制 0 的载波频率 |
| 波特率 | 1200 bps | 100–9600 bps | 符号速率；越低抗噪越强、传输越慢 |

> 收发双方 Mark/Space/波特率必须一致。默认 1200/2200/1200 为经典 AFSK 组合（兼容性好）。

### 7.4 纠错编码（FEC）

| 选项 | 默认 | 说明 |
|---|---|---|
| FEC 类型 | **Hamming** | None / Hamming / Reed-Solomon，见第 8 节 |

## 8. 纠错编码说明

音频链路（扬声器→麦克风、磁带机）存在不可避免的符号级错误（噪声、失真、爆音），纠错编码可显著提升解码成功率。

| 方案 | 纠错能力 | 数据开销 | 抗突发错误 | 推荐场景 |
|---|---|---|---|---|
| None | 无（1 位错误整帧作废） | 0% | 弱 | 仅无噪声数字链路（如直接拷贝 WAV 文件） |
| **Hamming(7,4)** | 每 7 位码字可纠 1 位 | +75% | 弱 | **短文本消息（默认，推荐）** |
| Reed-Solomon(255,239) | 每 255 字节块可纠 8 个错误字节 | +6.7% | **强** | **大文件传输** |

**选择建议**：

- **短消息（文本）**：用 **Hamming**。开销虽大但短消息总时长可接受，且对单点错误有纠正能力
- **大文件**：用 **Reed-Solomon**。RS 按 239 字节分块，开销小、抗连续错误强，适合长时传输
- 若链路质量很好（近距离、无噪声），可尝试 None 获得最短传输时间；失败率高时换回 Hamming

> 注：RS 对不足 239 字节的短消息会填充补位，导致传输时间变长，故短消息不推荐 RS。

## 9. 典型应用场景

### 9.1 磁带机传输（离线存储）

1. 发送端：发射面板输入文本 → **导出 WAV** → 用磁带机录制该 WAV 到磁带
2. 运输磁带到目标电脑
3. 目标电脑：磁带机播放 → 声卡录制为 WAV（可用 Audacity）→ **接收面板解析**

### 9.2 电台/近距离声波通信（实时）

1. 双方打开**电台**标签页，分别点击 **开始监听**
2. 一方输入文本/选择文件 → **发送**
3. 另一方自动解码显示，可立即回复 → 双向对话

### 9.3 回环自测（验证链路）

- 单台电脑：设置中确认输入/输出设备 → 电台页开始监听 → 发送文本 → 应看到自己的消息被解码回显（绿色 + 灰色各一条）
- 若回环成功而远距离失败，说明是链路衰减/噪声问题，可降低波特率或调近距离

## 10. 技术规格

| 项目 | 规格 |
|---|---|
| 调制方式 | AFSK（频移键控） |
| 默认参数 | Mark 1200 Hz、Space 2200 Hz、1200 bps、44100 Hz |
| 符号长度 | 36 样本 @ 44100 Hz |
| 帧结构 | 准备音(1s) → 类型帧 → 数据帧 → 帧尾静音(1s) |
| 帧头 | AA 55 |
| 类型帧 | 'T'（文本）/ 'F'（文件） |
| 校验 | CRC-16/CCITT（0x1021，初值 0xFFFF） |
| 纠错 | Hamming(7,4) / Reed-Solomon(255,239)，可关闭 |
| 支持格式 | 文本（UTF-8）、任意文件（≤ 100 KB 建议） |
| 音频格式 | PCM 16 位，22050 / 44100 / 48000 Hz，单/双声道 |

## 11. 常见问题排查

### 11.1 解码失败 / 解不出内容

按顺序检查：

1. **听一听录音**：应有"1 秒连续蜂鸣（准备音）+ 滋滋调制声"结构。若听到断续/卡顿/噼啪，说明发送端播放或录音链路有问题（设备欠载、音量过低）
2. **音量**：发送端输出音量和接收端输入音量适当调大（但避免削波失真——波形监视器顶部出现平顶即过载）
3. **参数一致**：确认收发双方采样率、Mark/Space 频率、波特率、FEC 设置完全一致
4. **录音完整**：确认录音包含准备音和数据部分，未从数据中间开始
5. **环境噪声**：远离风扇、空调等噪音源；使用磁带机时避免磁头脏污
6. **换 FEC**：失败时改选 Hamming（默认）重试；仍失败再试 None/RS 对比
7. **降低波特率**：链路质量差时在设置中降低波特率（如 600 bps），抗噪能力显著提升

### 11.2 声音断续 / 卡顿

- 增大设置中的**缓冲区大小**（如 1024 → 4096）
- 关闭其他占用声卡的软件（浏览器、播放器等）
- 确认音频驱动正常（设备管理器中声卡无感叹号）

### 11.3 电台监听不到信号

- 确认输入设备选择了正确的麦克风（设置 → 刷新设备）
- 发送方距离过远：拉近至 1~3 米
- 波形监视器应能看到信号波形；若完全平直，说明输入链路不通

### 11.4 安装后无法启动

- 确认安装的是完整组件（主程序为必选）
- 尝试右键 → 以管理员身份运行（个别系统需要）
- 卸载后重新安装最新版本

### 11.5 虚拟声卡（VB-CABLE 等）使用

- 在设置中将输入/输出设备分别指向虚拟声卡对应端点
- 虚拟声卡方案用于"无声传输"（扬声器不发声），但会引入额外延迟和爆音风险，优先推荐真实声卡链路
